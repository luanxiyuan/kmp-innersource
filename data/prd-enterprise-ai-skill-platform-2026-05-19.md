## 2. 用户故事

5个核心场景，覆盖4类用户画像：

### US-1 开发者·技能发现与接入
> 作为一名前端开发者，我刚刚被分配到一个新项目组，需要快速找到项目组内已有的代码审查Skill，以便在提交代码前自动运行审查，这样我不用从零搭建审查流程，效率提升30%以上。

**核心路径**：进入平台 → 按项目组筛选 → 搜索"代码审查" → 查看Skill详情（含使用技巧帖） → 一键接入项目 → 运行首次调用

### US-2 测试工程师·质量赋能转型
> 作为一名测试工程师，我想将自动化回归测试Skill发布到平台并分享给其他项目组，让更多人看到测试团队的技术价值，使测试团队从"成本中心"转型为"质量赋能中心"。

**核心路径**：登录平台 → 一键发布Skill → 等待审核通过 → 收到其他项目组使用通知 → 查看技术影响力报告

### US-3 业务人员·AI能力民主化
> 作为一名业务运营人员，我每周需要手动汇总5个项目的进度报告，耗时4小时。我想找到一个"项目进度自动汇总"Skill，不需要写代码就能配置使用。

**核心路径**：浏览"业务自动化"分类 → 查看通俗语言描述 → 查看技巧帖图文教程 → 一键试用 → 确认可用后接入

### US-4 客户经理·客户受限视图
> 作为甲方项目的负责人，我想查看外包团队为我方项目提供的AI能力清单和质量指标，确认数据隔离到位，但不应该看到其他客户项目的任何信息。

**核心路径**：登录客户专属入口 → 查看我方项目的Skill清单（脱敏） → 查看技能健康度指标 → 下载合规报告

### US-5 跨项目组·技能共创
> 作为项目组A的开发者，我发现项目组B有一个数据分析Skill非常好用，但需要适配我方项目的数据格式。我想Fork该Skill，修改后提交PR让原始作者Review。

**核心路径**：发现目标Skill → Fork到工作区 → 修改适配 → 提交PR → Review通过合并 → 双方获得贡献积分

## 3. 用户研究洞察（来自瑞思·用户研究员）

### 3.1 四类用户画像要点

| 用户类型 | 角色定位 | 核心痛点 | 核心期望 |
|----------|----------|----------|----------|
| 开发团队 | 主要生产者+重度消费者 | 技能散落各处、文档缺失、分享无激励 | 效率提升30%+、技术影响力可见化 |
| 测试团队 | 重要消费者+场景验证者 | 测试技能难发现、术语门槛高、测试工具不被视为Skill | 从"成本中心"转型为"质量赋能中心" |
| 业务团队 | 场景定义者+轻量消费者 | 不知道AI能做什么、技术门槛高、语言体系不同 | 业务流程自动化、AI能力民主化 |
| 客户（甲方） | 边界用户+信任验证者 | 数据安全担忧、外包透明度不足 | 数据隔离确认、服务质量可视 |

### 3.2 八条关键洞察

1. **技能的"可理解性"比"功能性"更决定采用率** — 每个Skill必须包含通俗描述，使用技巧帖是一等公民内容
2. **数据安全是企业内部平台的"一票否决"因素** — 客户数据隔离是生存条件，不是加分项
3. **外包公司的组织结构是内容分类和权限管理的骨架** — 组织架构是第一层导航，不是可选标签
4. **激励体系必须与职业发展路径挂钩** — Skill贡献应可导出为"技术影响力报告"，对接晋升评审
5. **"使用技巧帖"是连接技能生产者和消费者的关键桥梁** — 降低分享门槛，让非技术用户也能贡献
6. **技能的"版本治理"是规模化后的核心挑战** — 支持SemVer、LTS版本、变更影响分析
7. **客户的"受控可见性"是差异化的商业价值** — 让外包服务从"黑箱"变为"透明橱窗"
8. **平台冷启动需要"种子技能+种子用户"双轮驱动** — 上线前策展≥20个种子Skill

### 3.3 与C端平台本质差异

| 维度 | C端平台 | 企业内部平台 |
|------|---------|-------------|
| 用户动机 | 个人兴趣驱动 | 工作需要+职业发展 |
| 内容边界 | 开放无边界 | 封闭有边界，隔离是刚需 |
| 信任模型 | 社区信任 | 组织信任+合规审查 |
| 安全要求 | 相对宽松 | 企业级（一票否决） |
| 客户关系 | 无甲方概念 | 外包甲方是特殊用户群 |

> **核心结论**：不是"企业版小红书"或"内部GitHub"，而是**以组织架构为骨架、以安全隔离为底线、以业务场景为驱动**的知识共享与协作平台。

## 4. 竞品对比（来自竞析·竞品分析师）

### 4.1 WorkBuddy深度拆解

**可借鉴的设计模式**：
1. SKILL.md文件式技能定义 — 零代码自定义，极简创建
2. 专家角色切换机制 — 不同人格让AI输出更专业
3. 专家团多Agent协作 — 复杂任务分解→专家分工→并行执行
4. SkillHub一键安装 — 秒级生效
5. IM远程操控 — 契合企业即时通讯场景
6. 安全网关代理 — 避免内网穿透

**企业内部致命局限（3项🔴）**：
1. 无组织架构适配 — 完全面向个体，无团队/部门概念
2. 无数据隔离机制 — 不同客户/项目组数据混在一起
3. 无客户可见性管控 — 技能一旦发布即对所有人可见

## 7. 关键流程

### 7.1 消费主流程：发现并使用Skill

```
首页/搜索入口 → 搜索/分类/推荐 → Skill详情页
→ 阅读通俗描述+技巧帖 → 一键试用(沙箱)
→ 接入指引 → 复制CLI/API Key → 首次调用成功 ← WASI+1
```

**设计铁律**：<3次点击完成接入，5分钟内首次调用

### 7.2 贡献主流程：一键发布Skill

```
我的工作台 → 创建新Skill → 填写信息表单（技术+通俗双层描述必填）
→ 上传SKILL.md → 预览与自动校验 → 安全扫描 → 提交审核 → 发布成功
```

### 7.3 安全基座：权限管控

```
管理员后台 → 组织架构管理（导入/同步/配置客户映射）
→ 角色权限配置（全局+项目组级） → 客户隔离配置
→ 安全审计（操作日志/权限变更/数据访问/合规报告）
```

**原则**：安全"隐形嵌入"——普通用户无感知，后台自动执行

### 7.4 共创流程：Fork+PR+Review

```
Skill详情页 → Fork到工作区 → 修改适配 → 提交PR
→ 差异对比 → 原作者Review → 通过合并 / 驳回修改
→ 双方获积分 → 新版本通知已接入用户
```

### 9.2 Go/No-Go决策门
